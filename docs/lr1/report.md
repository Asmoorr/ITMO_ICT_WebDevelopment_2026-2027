# ЛР 1. Работа с сокетами

## Цель работы

Изучить взаимодействие клиента и сервера через сокеты: передачу датаграмм UDP,
обмен байтами по TCP, формирование HTTP-сообщений и параллельное обслуживание клиентов.

Выполнены пять заданий. Во втором используется **вариант 1 — теорема Пифагора**
для номера 33 в журнале: `(33 - 1) % 4 + 1 = 1`.
Чат реализован на TCP с использованием `threading`.

## Окружение

- Python **3.10 или новее** — требование проекта; примеры проверены на Python 3.13 в Windows.
- Приложения используют только стандартную библиотеку Python.
- Poetry поддерживается существующей конфигурацией проекта, но для запуска скриптов не обязателен.
- MkDocs и Material нужны отдельно для сборки отчёта.

Склонируйте репозиторий и перейдите в папку студента:

```powershell
git clone https://github.com/Asmoorr/ITMO_ICT_WebDevelopment_2026-2027.git
cd ITMO_ICT_WebDevelopment_2026-2027/students/k3341/Trikula_Artem
```

Все команды запуска заданий далее выполняются **из `students/k3341/Trikula_Artem`**.
Если используется Poetry, сначала выполните `poetry install`, а перед `python` добавляйте `poetry run`.

## Запуск

В отдельном терминале запустите сервер выбранного задания. Для заданий 1, 2 и 4
клиенты запускаются в других терминалах; для HTTP роль клиента выполняет браузер или `curl.exe`.

| Задание | Сервер | Клиент / адрес | Порт |
| --- | --- | --- | --- |
| 1 | `python Lr1/task1_udp/server.py` | `python Lr1/task1_udp/client.py` | UDP 9001 |
| 2 | `python Lr1/task2_tcp/server.py` | `python Lr1/task2_tcp/client.py` | TCP 9002 |
| 3 | `python Lr1/task3_http/server.py` | `http://127.0.0.1:8080/` | TCP 8080 |
| 4 | `python Lr1/task4_chat/server.py` | `python Lr1/task4_chat/client.py --username Artem` | TCP 9004 |
| 5 | `python Lr1/task5_grades/server.py` | `http://127.0.0.1:8081/` | TCP 8081 |

Сервер задания 1 завершается после одного обмена. Остальные работают до `Ctrl+C`.
Для выхода из чата используется `/quit`.

По умолчанию все серверы слушают `127.0.0.1`, поэтому доступны на том же компьютере.
Для чата адрес и порт можно задать аргументами `--host` и `--port` на сервере и клиенте.

## Протоколы

| Протокол | Как передаются данные | Применение в работе |
| --- | --- | --- |
| UDP | Отдельные датаграммы без установления соединения; доставка и порядок не гарантируются | Короткий обмен приветствиями |
| TCP | Упорядоченный поток байтов в установленном соединении; границы сообщений задаёт приложение | Вычисления и чат |
| HTTP поверх TCP | Строка запроса/статуса, заголовки, пустая строка, тело | HTML-страница и журнал оценок |

TCP может разбить одно сообщение между несколькими `recv()` или объединить несколько сообщений
в одном чтении. В чате эта особенность учтена буфером и разделителем `\n`.
В HTTP длина тела задаётся заголовком `Content-Length` и измеряется в байтах.
