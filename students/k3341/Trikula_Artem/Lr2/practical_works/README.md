# Практики Django 2.1–2.3

**Трикула Артём, K3341.** Один проект `django_project_trikula` и приложение `project_first_app` реализуют все три последовательные практики. Модели, формы, шаблоны, миграции и тесты используются совместно.

## Соответствие заданиям

| Практика | Реализация | Ключевые файлы приложения |

Модель пользователя задана до первой миграции. Связи с пользователем используют `settings.AUTH_USER_MODEL`. DjangoTemplates сохраняет синтаксис учебных примеров; Jinja2 относится к отдельному основному варианту конференций.

## Запуск

Из `students/k3341/Trikula_Artem`, в существующем окружении Poetry:

```powershell
poetry install
poetry run python Lr2/practical_works/manage.py migrate
poetry run python Lr2/practical_works/manage.py seed_demo
poetry run python Lr2/practical_works/manage.py runserver 127.0.0.1:8001
```

Откройте [реестр](http://127.0.0.1:8001/) или [Admin](http://127.0.0.1:8001/admin/). Для остановки сервера, запущенного из терминала, — `Ctrl+C`.

Настройки читаются из `Lr2/.env` по абсолютному пути. `POSTGRES_PRACTICES_DB` задаёт рабочую базу. При объединении база итогового этапа переименована в `lr2_practices`: пользователи, хеши паролей, миграции и записи сохранены. Другие исторические базы не используются проектом.

Администратор — `admin`, обычные пользователи — `owner1`–`owner6`. Первоначальный пароль — `DJANGO_DEMO_PASSWORD` из локального `.env`. Команда наполнения не сбрасывает существующие пароли и не удаляет данные. Все паспортные номера, адреса и удостоверения вымышлены.

## Модель и данные

| Модель | Назначение |
|---|---|
| `CarOwner` | Учётная запись, имя, фамилия, дата рождения, паспорт, адрес, национальность |
| `Car` | Уникальный госномер, марка, модель, необязательный цвет |
| `Ownership` | Владелец, автомобиль, начало и необязательное окончание владения |
| `DriverLicense` | Уникальный номер удостоверения, категория из `TextChoices`, дата выдачи, владелец |

После наполнения — шесть владельцев и администратор, семь автомобилей, шесть владений и шесть удостоверений. У первых двух владельцев по три автомобиля в истории; переходы между владельцами не пересекаются.

M2M `Car.owners` использует `through="Ownership"`. Удостоверения связаны с владельцем отношением один-ко-многим. Обе границы периода владения включены; пустое окончание означает продолжающееся владение. Следующий владелец начинает владение на следующий день после продажи.

`CheckConstraint` запрещает обратный порядок дат, exclusion constraint с `DATERANGE` — пересечения для одного автомобиля. Миграция устанавливает `btree_gist`; владелец базы должен иметь право установить это доверенное расширение. `clean()` и inline formset показывают ошибки в Admin, включая пересечения нескольких новых записей одной формы.

Отличия от рисунка методички: календарные даты — `DateField`, участники связи владения обязательны, госномер и номер удостоверения уникальны.

## Страницы и права

| Метод | URL | Реализация и доступ |
|---|---|---|
| GET | `/` | Сотруднику — список владельцев, пользователю — свой профиль, гостю — вход |
| GET | `/owners/` | FBV `owner_list`, только сотрудники |
| GET | `/owner/<id>/` | FBV `owner_detail`, сам пользователь или сотрудник |
| GET, POST | `/owners/create/` | FBV `owner_create`, открытая регистрация через `UserCreationForm` |
| GET | `/cars/` | `CarListView`, открытый каталог |
| GET | `/cars/<id>/` | `CarDetailView`, без паспортов и адресов владельцев |
| GET, POST | `/cars/create/` | `CarCreateView`, только сотрудники |
| GET, POST | `/cars/<id>/update/` | `CarUpdateView`, только сотрудники |
| GET, POST | `/cars/<id>/delete/` | `CarDeleteView`, только сотрудники; GET показывает подтверждение |
| GET, POST | `/accounts/login/` | Вход через штатную аутентификацию Django |
| POST | `/accounts/logout/` | Выход с CSRF-защитой |
| GET, POST | `/admin/` | Управление моделями и дополнительными полями пользователя |

Есть поиск и пагинация с сохранением запроса. Шаблоны экранируют текст. Формы содержат явный список полей; подмена POST не позволяет назначить себе staff/superuser. Изменения требуют CSRF-токен; права проверяются на сервере.

## Проверки

Общий набор из **20 тестов** покрывает модель, ограничения PostgreSQL, Admin, FBV/CBV, CRUD, создание трёх владельцев и трёх автомобилей через HTTP-формы, регистрацию, пароли, личные данные и CSRF. Повторяющиеся проверки отдельных этапов объединены.

```powershell
poetry run python Lr2/practical_works/manage.py check
poetry run python Lr2/practical_works/manage.py makemigrations --check --dry-run
poetry run python Lr2/practical_works/manage.py test project_first_app --settings=django_project_trikula.test_settings --keepdb --noinput
poetry run ruff check Lr2/practical_works
```

Тесты используют отдельную `test_lr2_practices` и роль `lr2_test` без `CREATEDB`. База создана заранее; `--keepdb` обязателен. Рабочие данные при тестировании не меняются.

## Оформление

Практики используют локальный Roboto и CSS-адаптацию темы Material UI 9.5.0. Основной текст и поля ввода имеют размер 16 px, подписи — 14 px, заголовки страниц — 30–36 px. Списки представлены таблицами с поиском; карточка владельца разделена на данные профиля, историю владения и удостоверения. Ссылки не подчёркиваются, фокус клавиатуры выделен контуром. Подсказки под полями и нижний колонтитул удалены, ошибки валидации сохранены.
