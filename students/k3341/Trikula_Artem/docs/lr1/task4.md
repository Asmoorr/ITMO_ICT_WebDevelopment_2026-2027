# Задание 4. Многопользовательский чат

## Архитектура

Один сервер на `127.0.0.1:9004` обслуживает несколько экземпляров **одного** `client.py`.
Для каждого подключения создаётся отдельный `threading.Thread`, выполняющий `handle_client()`.
Участник выбирает имя и может выйти командой `/quit`.

`ChatServer` отвечает за подключения, регистрация, рассылка, удаление участников <br>
`ClientSession` за сокет, имя, готовность к рассылке, блокировка отправки <br>
`client.py` - подключение, ввод пользователя, получение сообщений <br>
`protocol.py` - сериализация JSON, разбор потока, закрытие сокета <br>

Сервер хранит участников в `dict[str, ClientSession]`, ключ — имя после `casefold()`.
Имя содержит 1–24 символа: буквы, цифры или `_`. Сравнение имён не зависит от регистра.

## Прикладной протокол

Каждое сообщение — JSON-объект в UTF-8, завершающийся байтом `\n`.
Максимальная длина кадра без разделителя — 16 КБ; текста сообщения — 2000 символов.

| Направление        | Тип       | Пример                                                     |
|--------------------|-----------|------------------------------------------------------------|
| Клиент → сервер    | `join`    | `{"type":"join","username":"Artem"}`                       |
| Сервер → клиент    | `welcome` | `{"type":"welcome","username":"Artem"}`                    |
| Клиент → сервер    | `chat`    | `{"type":"chat","text":"Привет всем!"}`                    |
| Сервер → остальные | `chat`    | `{"type":"chat","username":"Artem","text":"Привет всем!"}` |
| Клиент → сервер    | `quit`    | `{"type":"quit"}`                                          |
| Сервер → остальные | `system`  | `{"type":"system","text":"Anna вышел из чата"}`            |
| Сервер → клиент    | `error`   | `{"type":"error","text":"Имя уже занято"}`                 |

## Границы сообщений и потоки

`receive_messages()` добавляет фрагменты TCP в `bytearray`, извлекает все завершённые
строки JSON и сохраняет остаток для следующего чтения. Это позволяет получать кадр частями
или несколько кадров за одно чтение. Незавершённое сообщение при закрытии соединения
считается ошибкой.

Общие словари сервера защищены `clients_lock`. Список получателей копируется под блокировкой,
а сеть обслуживается после её освобождения. Отдельный `send_lock` каждого участника
не даёт потокам перемешать отправляемые ему кадры.

На клиенте отдельный поток получает сообщения, фоновый поток читает консоль,
а основной отправляет строки из очереди. `threading.Event` координирует регистрацию и остановку.
При `/quit`, разрыве соединения или ошибке сервер удаляет сессию и уведомляет остальных.
При остановке сервер закрывает подключения и ожидает завершения рабочих потоков.

## Пример запуска сервера и трёх участников

```powershell
# Сервер
python Lr1/task4_chat/server.py

# Первый участник
python Lr1/task4_chat/client.py --username Artem

# Второй участник
python Lr1/task4_chat/client.py --username Anna

# Третий участник
python Lr1/task4_chat/client.py --username Ivan
```

Для изменения адреса и порта:

```powershell
python Lr1/task4_chat/server.py --host 127.0.0.1 --port 9014
python Lr1/task4_chat/client.py --host 127.0.0.1 --port 9014 --username Artem
```
